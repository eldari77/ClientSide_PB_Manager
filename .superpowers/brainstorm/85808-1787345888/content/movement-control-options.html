Ship Movement Control

With a 0.3 ms global PB cap, the movement primitive matters more than the stance names. The client can plan patrol, guard, and pursue, but the receiver PB needs the cheapest safe actuator path.

A. Remote Control Waypoints
Client computes waypoint / heading goal
↓ tiny packet
Receiver PB updates Remote Control
↓ game autopilot
Ship flies the leg

Cheapest If Allowed

Best runtime profile. Depends on Remote Control/autopilot being available and good enough on this server.

B. Direct Thruster/Gyro Commands
Client computes control vector
↓ per-step packet
Receiver PB applies gyro/thrust overrides
↓
Ship steers manually

Most Independent

Can work without autopilot, but costs more PB time and needs careful stabilization, failsafes, and testing.

C. Hybrid Autopilot + Corrections
Remote Control handles travel
+
PB applies small facing / braking / block actions
+
Client refreshes tactical intent

Likely Best V1

Uses the cheapest movement path first, while leaving room for guard-facing, pursue-brake, and combat posture commands.

Question

On this server, are Remote Control blocks and their autopilot/waypoint behavior available and acceptable for combat ships?
